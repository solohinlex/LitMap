# LitMap — вопросы и сводки по литературным корпусам

Работает через CLI `litmap` из проекта LitMap (пакет переиспользуется). Реестр
проектов и sqlite-индексы глобальные (`~/.config/litmap/`, `~/.local/share/litmap/`),
поэтому скилл доступен из любой папки.

## Разделение ролей (важно)

- **Индексация и эмбеддинги** остаются на выделенном сервере «nomad» (эмбеддинг-
  эндпоинт из `.env`, например `nomic-embed-text` на `127.0.0.1:11434`). Скилл не
  трогает этот механизм.
- **Ответ на вопрос формулирует текущая модель opencode** — НЕ чат-эндпоинт litmap.
  Для этого litmap используется в режиме `--context`: он извлекает релевантные
  чанки (векторный + текстовый поиск), а модель читает их и пишет ответ сама.

## Окружение

Если команда `litmap` недоступна — установить пакет:

```bash
pip install -e ".[dev]"
```

в каталоге проекта LitMap (там, где лежит `pyproject.toml`), затем убедиться, что
`.env` (или `LITMAP_EMBED_BASE_URL`/`LITMAP_EMBED_MODEL`) указывает на рабочий
эмбеддинг-сервер. Проверка: `litmap --help`.

## Команды

### 1. Добавить проект по папке

```bash
litmap projects add <имя> --corpus <путь/к/папке>
```

- `<имя>` — латиница, цифры, дефис, подчёркивание (см. `validate_project_name`).
- Имя проекта задаёшь сам: возьми имя верхней папки корпуса; если папка уже
  зарегистрирована — просто переиспользуй её имя (`litmap projects list`).
- Корпус может содержать несколько папок — передавай `--corpus` несколько раз.
- Папки корпуса только читаются, ничего в них не пиши.

### 2. Переиндексировать проект

```bash
litmap -p <имя> index
```

Читает папки, чанкирует, строит эмбеддинги (на «nomad») и обновляет sqlite-индекс.
Выводит статистику: документов, обновлено, удалено, чанков.

### 3. Запрос по проекту (ответ — текущей моделью)

```bash
litmap -p <имя> ask "<вопрос>" --context
```

Опционально ограничить одной рукописью:

```bash
litmap -p <имя> ask "<вопрос>" --context --work "<название верхней папки рукописи>"
```

Команда выводит только извлечённый контекст (чанки в виде `### файл: <путь> — <заголовок>`
с текстом). Типы запросов определяются автоматически (свободный вопрос, персонаж,
глава, сюжетная линия) — тот же маршрутизатор, что и в `ask` без `--context`.

**После получения контекста модель обязана:**
1. Прочитать выведенные чанки.
2. Сформулировать ответ **сама, по-русски**, опираясь только на предоставленный
   контекст.
3. Сослаться на источники (пути файлов/названия глав) из контекста.
4. Если контекст пуст (вывод «не найдено фрагментов») — честно сообщить, что по
   запросу в проекте ничего не нашлось.

## Примечания

- Проект можно задавать и через `LITMAP_PROJECT` или работая внутри папки корпуса,
  но явное `-p <имя>` надёжнее — используй его.
- `--work` ограничивает поиск одной рукописью + общими `characters/`/`lore/`.
- Все ответы пользователю — на русском.
